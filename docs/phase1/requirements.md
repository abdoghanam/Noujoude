## 1. نطاق المشروع (Scope)

### ✅ مؤكد
- **موقع محتوى / منصة شخصية** — وليس SaaS.
- **لا** حسابات مستخدمين، **لا** اشتراكات، **لا** لوحات تحكم ديناميكية — إلا بموافقة مستقلة لاحقة.
- **اللغات والجمهور (D4 — معتمد):** **الجمهور عالمي.** العربية (RTL) والإنجليزية (LTR) **لغتان متساويتان في الأهمية** من حيث تجربة المستخدم وجودة التصميم وإتقان المحتوى — لا تُعامل الإنجليزية كبديل ثانوي. العربية تظل لغة المسار الافتراضي للتحويل `/` → `/ar` (Q4) — وهذا **قرار توجيه تقني** وليس ترتيبًا للأهمية.
- التقنيات: Next.js + TypeScript + Tailwind CSS + MDX + ESLint + Prettier + Vitest + Playwright (ما لم يوجد سبب هندسي موثق للتغيير).
- حوكمة المشروع: مراحل مع بوابات موافقة، صدق في التقارير، لا أسرار في المستودع.

## 3. تجربة المستخدم (UX)

### ✅ مبدأ متساوي اللغتين (D4 — معتمد)
النبرة، عمق التصميم، وضوح النص، وترتيب المحتوى **متساويان** للعربية والإنجليزية. لا نصوص إنجليزية معادة من العربية بجودة أقل (أو العكس) — كل لغة تُكتب وتُراجع بلغتها.

### التدفقات الأساسية 💡 (تُعتمد ضمن التصميم لاحقًا)
1. **زائر جديد:** يفتح الموقع (`/` يُحوَّل إلى `/ar` افتراضيًا — Q4-A، لا كشف لغة آلي) → يقرأ الصفحة الرئيسية → يتصفح المقالات → يقرأ مقالًا → يبدّل اللغة إن أراد → يعود للرئيسية.
2. **قارئ عائد:** يفتح المقال مباشرة (رابط محفوظ/بحث) → يقرأ → يستكشف مواضيع مشابهة (وسوم).

### البنية التفاعلية 💡
- **الهيدر:** شعار/اسم **NOUJOUDE — نجود** (D1-B — هوية معتمدة) | روابط التنقل | مبدّل اللغة (AR/EN) — ثابت، ينهار لقائمة تنقل على الجوال.
- **التذييل:** روابط ثابتة + حقوق النشر + روابط الشبكات الاجتماعية (❓ إن وُجدت).
- **الجوال أولًا:** جميع الصفحات عند 375px و 768px و 1280px+.
- **تجربة القراءة:** عرض أقصى للنص 65–75 حرفًا/سطر، تباعد أسطر مريح للعربية (1.8+).
- **الوضع الداكن 💡:** اختياري — إن نُفّذ فيُنفذ لكل الصفحات دون استثناء.

### الشاشات المطلوب اختبارها
`375×667` (جوال) · `768×1024` (لوحي) · `1440×900` (كمبيوتر)

## 4. استراتيجية المحتوى (Q2-A — شرط نشر إلزامي)

### ✅ مؤكد
- المحتوى يُنشأ بـ **MDX** داخل المستودع (بدون CMS — لا خدمات خارجية دون موافقة).

### ✅ قاعدة التكافؤ — **شرط نشر** (Q2-A)، وليست هدفًا اختياريًا
> **يجب أن تتوفر لكل مقال منشور نسخة عربية ونسخة إنجليزية مرتبطة بالـ `slug` نفسه. لا يُنشر المقال إذا كانت نسخته المقابلة مفقودة.**

- هذه **بوابة نشر إلزامية** تُفحص آلية في كل بناء إنتاجي.
- 💡 آلية التنفيذ الموصى بها (تُعتمد عند المرحلة 3): فشل صريح في `next build` عند غياب أي نسخة مقابلة — رسالة خطأ تحدد المقال واللغة الناقصة. (استبعاد صامت للمقال أو 404 مقصود = **غير متوافق** مع القرار المعتمد.)

### 💡 بنية المحتوى (توصية — تُعتمد ضمن التنفيذ)

```text
content/
├── ar/
│   └── articles/
│       └── <slug>.mdx
└── en/
    └── articles/
        └── <slug>.mdx
```

**Frontmatter مطلوب لكل مقال:**

```yaml
title: string          # مطلوب
description: string    # مطلوب — للـ meta وملخص القائمة
date: YYYY-MM-DD       # مطلوب
tags: string[]         # مطلوب (حد أدنى 1)
cover: string          # اختياري — مسار صورة داخل public/
draft: boolean         # اختياري — يُستبعد من البناء الإنتاجي
```

### قواعد النشر
- التكافؤ أعلاه **إلزامي** (Q2-A) — يُفحص آليًا في الاختبارات والبناء.
- البيانات الوصفية (metadata) لكل لغة تُكتب بلغتها — لا ترجمة آلية.

### ❓ NEEDS USER INPUT (لا يمنع التخطيط)
- من يكتب المحتوى؟ ما حجم الدفعة الأولى؟ (حتى نحدد عدد المقالات الافتتاحي)
- ✅ ~~⛔ مرتبط بـ D3~~ **حُدِّث (D3-B):** التصنيفات الخمسة معتمدة — أي وسوم تفصيلية داخل المقال تُعتمد مع المحتوى الفعلي (لا اختلاق خارج القطاع المعتمد).

## 5. دعم اللغتين (i18n) — Q4-A معتمد

### ✅ القرارات المعتمدة رسميًا (Q4-A)
| القرار | القيمة المعتمدة |
|---|---|
| المكتبة | **`next-intl@4`** |
| بنية المسارات | **`/ar/...` و `/en/...`** |
| توجيه `/` | **تحويل المسار `/` إلى `/ar` افتراضيًا** (التوجيه حسب `Accept-Language` **لم يُعتمد**) |

### ✅ مؤكد
- العربية RTL والإنجليزية LTR — وكلاهما متساويان في الأهمية (D4).

### 💡 توصيات تفصيلية (غير معتمدة بعد — لا تؤثر على اعتماد Q4)
| القرار | التوصية |
|---|---|
| ملفات الترجمة | `messages/ar.json`, `messages/en.json` للنصوص الثابتة (قائمة، أزرار، أخطاء) |
| `<html dir>` | `rtl` لـ ar، `ltr` لـ en — من layout ديناميكي |
| تبديل اللغة | يحافظ على نفس المسار النسبي + `hreflang` صحيح |

### معايير القبول (i18n)
- لا نص "معطوب" أو يخرج من حدود الشاشة في أي اتجاه.
- تبديل اللغة يعمل من أي صفحة ويحافظ على الموضع النسبي.
- أرقام/تواريخ محلية: `ar` تظهر بتنسيق عربي عند الحاجة (تحقق يدوي + اختبار).
- `lang` و `dir` صحيحان على `<html>` لكل لغة.

## 6. SEO

### ✅ إلزامي
| البند | المتطلب |
|---|---|
| `<title>` و `<description>` | فريد لكل صفحة ولكل لغة |
| canonical | لكل صفحة — لغتها الصحيحة |
| hreflang | `ar` ↔ `en` + `x-default` |
| sitemap.xml | يتضمن كل الصفحات المنشورة باللغتين مع `xhtml:link` alternates |
| robots.txt | السماح بالزحف، منع غير المطلوب |
| Open Graph + Twitter Card | لكل صفحة |
| JSON-LD | `WebSite` + `BreadcrumbList` + `Article` للمقالات |
| صفحة 404 | تُرجع HTTP 404 فعليًا (ليست 200) عبر `not-found.tsx` لأي مسار غير مطابق — لا مسار `/404` مستقل مطلوب |

### 💡 توصيات
- صور OG مولَّدة لكل مقال (Dynamic OG Image) — تُقيَّم تكلفتها لاحقًا.
- RSS لكل لغة.

### ❓ NEEDS USER INPUT
- النطاق النهائي (D2 — مؤجل) — لضبط canonical وإنتاج الروابط الدائمة قبل النشر.

## 7. إمكانية الوصول (Accessibility) — Q3-A معتمد

### ✅ **WCAG 2.2 AA بوابة قبول إلزامية** (قرار Q3-A)
تُتحقق بـ **اختبارات آلية** (axe-core ضمن Playwright) **ومراجعة يدوية**. لا يُعلَّم المشروع جاهزًا ما لم يُستوفَ جميع مستويات الوصول المطلوبة.

| المجال | المتطلب |
|---|---|
| لوحة المفاتيح | كل عنصر تفاعلي قابل للوصول + مؤشر تركيز مرئي (focus-visible) |
| التنقل | Skip-to-content link + `<nav>` دلالية + هرمية عناوين صحيحة h1→h2→h3 |
| التباين | ≥ 4.5:1 للنص العادي، ≥ 3:1 للنص الكبير والعناصر الكبيرة |
| الصور | `alt` وصفي (أو `alt=""` للزخرفية) |
| الحركة | احترام `prefers-reduced-motion` |
| التكبير | عمل سليم حتى 200%، ودعم zoom 400% دون فقدان محتوى |
| RTL | انعكاس صحيح بدون كسر العناصر |
| التحقق الآلي | فحص `axe-core` — صفر `critical` و `serious` |
| التحقق اليدوي | مراجعة يدوية موثقة (قوائم/قارئ شاشة/تنقل بلوحة المفاتيح) — قائمة تحقق تُرفق بتقرير بوابة المرحلة 5 |

## 8. الأمان والخصوصية (نطاق الموقع — المرحلة 4)

### ✅ مؤكد (من الحوكمة)
- لا أسرار/كلمات مرور/API keys في المستودع أو التقارير أو الواجهة.
- لا إدخال بيانات مستخدم ديناميكي → مخاطر هجمات حقن الإدخال (SQLi، وXSS القائم على إدخال المستخدم) **منخفضة مبدئيًا وليست منعدمة**: يبقى محتوى MDX والروابط/الصور الخارجية مسارات محتملة إذا جاء مصدر المحتوى غير موثوق — الضابط الأساسي **سياسة المصدر الموثوق** (البند أدناه)، والمعالجة الإضافية تُقيَّم في المرحلة 4 (تحقق الروابط، CSP) — **دون اعتماد التنقية كحماية عامة**.

### 💡 متطلبات أمان موصى بها (تُعتمد في المرحلة 4)
| البند | المتطلب |
|---|---|
| الترويسات | `Content-Security-Policy` (تبدأ بـ report-only عند التقييم)، `X-Content-Type-Options: nosniff`، `Referrer-Policy`، `Permissions-Policy`، `Strict-Transport-Security` (عند النشر HTTPS)، `frame-ancestors 'none'` |
| HTTPS | إلزامي في الإنتاج |
| التبعيات | `package-lock.json` مُثبَّت، فحص دوري `npm audit` — التقرير يُنشر بكل نتائجه (لا إخفاء) |
| MDX | لا يُجمَّع أو يُعرض أي MDX إلا من مستودع موثوق ومراجع: مؤلفون معروفون، مراجعة عبر pull request — لا رفع ملفات من الزوار. **التنقية (sanitization) لا تُعتمد كحماية عامة** للمحتوى غير الموثوق (متسقًا مع `architecture.md` §5) |
| الكوكيز | الموقع لا يضع كوكيز تتبّع. كوكيز لغة واحدة عند الحاجة (`Lax`, `SameSite`) |
| خدمات خارجية | **لا** تحليلات/تتبع خارجي دون موافقة صريحة |
| التخزين | لا `localStorage` لبيانات حساسة |

### ❓ مفتوح
- هل يُفعَّل تحليلات (privacy-respecting مثل Umami/Plausible) لاحقًا؟ — خارج النطاق حتى موافقة.

## 9. الاختبارات ومعايير القبول ✅ (من الحوكمة + Q2-A + Q3-A)

| الطبقة | الأداة | معيار القبول |
|---|---|---|
| التنسيق | Prettier | صفر تنبيهات |
| Lint | ESLint (-next) | صفر أخطاء |
| الأنواع | `tsc --noEmit` | صفر أخطاء |
| الوحدة | Vitest | 100% من الاختبارات المكتوبة تنجح — تغطي: منطق i18n، قراءة/فرز MDX، توليد sitemap، دوال SEO، **فحص تكافؤ المقالات (Q2-A)** |
| E2E | Playwright | سيناريوهات: تنقّل، تبديل لغة، RTL/LTR، مقال كامل، 404، جوال+كمبيوتر |
| الوصول (آلي) | axe-core (ضمن Playwright) | صفر `critical` و `serious` |
| الوصول (يدوي) | مراجعة يدوية موثقة | قائمة تحقق WCAG 2.2 AA كاملة (Q3-A) |
| **التكافؤ (شرط نشر)** | فحص بناء إنتاجي | **فشل البناء** إن غابت نسخة لغة لأي slug منشور (Q2-A) |
| الروابط | فحص روابط داخلي | صفر روابط مكسورة |
| الأداء | Lighthouse | ≥ 90 في الأداء/الوصول/SEO (على بناء إنتاجي محلي) |
| بناء إنتاج | `next build` | ينجح بلا أخطاء |
| الأمان | `npm audit` + فحص الأسرار | لا ثغرات `critical/high` غير مبرَّرة، صفر أسرار |

**قاعدة:** لا اختبار فاشل يُتجاوز لإظهار نجاح. الفشل يُسجَّل ويُعالج أو يُوثَّق استثناءه بموافقة.
